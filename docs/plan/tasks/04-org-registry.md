## Зачем

Сейчас орг-структура живёт в двух местах: группы Keycloak в `realm.yml` и
DEV-зеркало `org_id` на пользователях. Любое переименование подразделения —
ручная правка realm плюс ручная правка атрибута у каждого пользователя; при
расхождении `org_id` в токене перестаёт соответствовать данным.

Реестр делает `org_id` управляемым master data: дерево хранится в Postgres,
группы и атрибуты Keycloak приводятся к нему синхронизацией. После задачи
переименование узла не меняет `org_id`, а значит не рвёт привязки данных и
фильтры тенанта.

## Что входит

1. **Домен.** `OrgUnit`: `OrgId` (UUID, неизменяемый), `ParentId`, `Name`,
   `Path` (например `/reon/hq/finance`), `IsService` (служебная группа
   `/reon/admins`, не организация), временные метки. Инварианты: `org_id`
   генерируется при создании и не меняется; путь уникален; перемещение узла
   пересчитывает пути потомков.
2. **Хранение.** EF Core, отдельная база `reon_auth` в контейнере Postgres
   стенда (init-скрипт, идемпотентный). Миграции схемы. Индекс по
   `org_id`, уникальный индекс по `path`.
3. **Admin API.** CRUD дерева: создать узел, переименовать, переместить,
   получить дерево. Все операции — под политиками capability по стандарту
   (`org:manage` для изменений, `org:read` для чтения), с учётом тенанта.
   curl-примеры — в отчёте задачи.
4. **Синхронизация с Keycloak.** Воркер (background service) и клиент
   `IKeycloakAdminClient`: создаёт отсутствующие группы, переименовывает
   изменившиеся, проставляет атрибут `org_id` из реестра. Синхронизация
   идемпотентна, повторный прогон не меняет состояние. Группы с живыми
   пользователями не удаляются без явного флага.
5. **Тесты.** Unit на инварианты домена; интеграционные на EF и миграции
   (Testcontainers Postgres); converge-тест «реестр ≠ Keycloak → сходятся»;
   идемпотентность; переименование сохраняет `org_id`; dev-only сценарий
   против живого стенда.

## Что не входит

- UI управления деревом (только API и curl).
- Делегирование доступа между тенантами — задача 07.
- Миграция исторических данных: данных пока нет.
- Замена штатного attribute-mapper `org_id` на пользователях — задача 08.
- Отдельный кластер Postgres: используется стенд.

## Риски

- **Гонка с ручными правками в админке Keycloak**: синк перезапишет ручное
  изменение. Меру: ручные правки групп — вне процесса, фиксируется в
  документации после приёмки.
- **Права сервисного аккаунта**: `reon-service` должен иметь ограниченные
  роли realm-management (users/groups), не global admin; нужен отрицательный
  тест на лишние права.
- **Модель `OrgUnit` может не покрыть правила задачи 07**: держим минимум —
  дерево и `org_id`, без атрибутов политик.
