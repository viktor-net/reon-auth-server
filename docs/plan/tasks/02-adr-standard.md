# Задача 02 — ADR и стандарт подключения сервисов

## Зачем

Нужно зафиксировать архитектурные решения (иначе каждое изменение стандарта
обсуждается заново) и дать модулям пошаговый стандарт подключения, чтобы
новый сервис подключал аутентификацию и базовую авторизацию за часы.

## Что входит

1. **ADR** `docs/adr/0001-authn-authz-architecture.md`: контекст (включая
   предшественника — ADR 04.01.04 на Spring), шесть **альтернатив
   архитектуры авторизации** (гибрид RBAC и ABAC с проверкой внутри приложения, ReBAC, внешний
   policy engine, RLS, собственный IdP, «только Keycloak без кода» — это не
   способы подключения к Keycloak), решение, последствия, таблица перевода
   Spring к нашим условиям, место СУДИР и BFF, открытые вопросы с владельцами.
2. **Стандарт** `docs/standards/service-auth.md` версии 1.0:
   - схемы по типам клиентов (SPA dev-only напрямую, backend-модуль с bearer
     JWT, сервис→сервис по client_credentials, BFF отложен, ROPC dev-only);
   - контракт JWT и правила чтения claims (организация по `org_id`, `groups`
     только для иерархии, `/reon/admins` — служебная);
   - требования к валидации (issuer, audience, подпись RS256, clock skew,
     лимиты заголовков);
   - модель авторизации: `MASTER_ADMIN` → capability → тенант и иерархия,
     плюс сервисные эндпоинты по `aud` и `azp`;
   - требования к реализации, тестирование с mock-токенами и негативные
     сценарии, чек-лист подключения модуля, curl-примеры DEV.

## Что не входит

- Код приложений и тесты — вне этой задачи.
- Реестр орг-структуры (04), СУДИР (05), BFF (06), детальные правила (07).
- Продуктовые практики (08).

## Критерии приёмки

- [x] ADR содержит контекст, не менее четырёх альтернатив, решение,
      последствия и соответствие терминам предшественника.
- [x] Стандарт покрывает все типы клиентов, валидацию, контракт claims,
      лимиты заголовков, запрет ROPC вне DEV, mock-токены, чек-лист.
- [x] Curl-примеры воспроизведены на живом стенде (discovery 200,
      client_credentials, ROPC, `expires_in=900`).
- [x] Язык по AGENTS.md §16, «TODO» и «см. позже» отсутствуют.

## Итог и правки после ревью

Ревьюер вернул документы с дефектами; исправлено в attempt 2:

- JWKS-путь: `{issuer}/protocol/openid-connect/certs` (старый давал 404);
- вложенный `realm_access.roles` не раскрывается JwtBearer — добавлен
  flattening в `OnTokenValidated` и политика `RequireRole`;
- для http-стенда добавлен `RequireHttpsMetadata = false` с пометкой DEV;
- добавлен раздел 2.1 с инструкцией подключения SPA (PKCE S256, токены
  только в памяти, refresh в окне 8 ч, logout через `end_session_endpoint`);
- уточнено понятие тенанта (`org_id` — якорь организации, иерархия — пути
  групп) и источник пути узла ресурса;
- добавлены сервисные эндпоинты по `aud` и `azp` и пример политики;
- убран лишний параметр `audience` из curl: его проставляет mapper.
