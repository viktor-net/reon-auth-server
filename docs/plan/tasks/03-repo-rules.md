# Задача 03 — Правила репозитория и нормализация окончаний строк

- **task-id:** `local-20261101-03`, size **S**, **закрыта**
- **зависимости:** 01 (стенд, который надо не сломать нормализацией)
- **доска:** `.agents/tasks/local-20261101-03/`

## Зачем

До этой задачи в репозитории не было единых правил: редакторы сохраняли файлы
кто с CRLF, кто с LF, из-за чего диффы показывали изменения во всех строках, а
скрипты, скопированные в Linux-контейнер, могли перестать запускаться.

Правила должны появиться до первого кода, иначе их пришлось бы вводить поверх
уже испорченной истории.

## Что входит

1. **`.editorconfig`** — отступы, кодировка, окончания строк и завершающий
   перевод строки для всех типов файлов репозитория.
2. **`.gitattributes`** — режим хранения: в репозитории LF, в рабочей копии
   CRLF; исключения для `Dockerfile`, `.dockerignore`, `*.sh`, `*.conf`,
   `*.py`; бинарные файлы помечены отдельно.
3. **`.gitignore`** — исключения для секретов, артефактов сборки, PDF
   заказчика, локальной доски задач и рабочих копий.
4. **Нормализация существующих файлов** — приведение всех текстовых файлов к
   режиму из CONTRIBUTIONS.md и проверка, что стенд после этого работает.

## Что не входит

- Код приложений и тесты.
- Изменение содержимого документов и конфигурации стенда, кроме окончаний
  строк.
- Настройка CI.

## Файлы

`.editorconfig`, `.gitattributes`, `.gitignore`, а также окончания строк во
всех текстовых файлах репозитория.

## Критерии приёмки

- [x] Все текстовые файлы соответствуют режиму: CRLF в рабочей копии, LF для
      скриптов и конфигов.
- [x] `scripts/smoke-auth.sh` и `scripts/smoke-auth.ps1` запускаются после
      нормализации, проверки зелёные.
- [x] Инициализация realm проходит с кодом 0 (CRLF в YAML не ломает импорт).
- [x] Правила `.gitattributes` и `.editorconfig` не противоречат
      CONTRIBUTIONS.md.

## Риски

- Массовая конвертация затрагивает все файлы сразу: ошибку легко не заметить.
  Мера — прогон smoke и инициализации после конвертации, а не только `git status`.
- Смешанные окончания внутри одного файла Visual Studio показывает как
  конфликт; после нормализации таких файлов быть не должно, проверка описана в
  CONTRIBUTIONS.md.
